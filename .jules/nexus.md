# Nexus Logic Log

## 2026-02-25 — [Document Workflow] **Проблема:** Пользователи (Согласующие) не могли отклонить документ. В интерфейсе была только кнопка "Согласовать" (Forward), а в API отсутствовал метод `reject`. Это создавало логический тупик для некорректных документов. **Решение:** Добавлен эндпоинт `PUT /api/documents/:id/reject` в `documentController.ts` и кнопка "Отклонить" в `DocumentDetail.tsx`. Логика меняет статус документа и текущего согласующего на `REJECTED`. **Безопасность:** Использованы существующие статусы базы данных (`REJECTED`). Логика согласования (`forward`) не затронута. Тесты подтвердили, что только текущий согласующий может выполнить действие.

## 2026-02-25 — [Security / Document Workflow] **Проблема:** Пользователи (в т.ч. Администраторы и Авторы) могли редактировать текст документа после отправки на согласование (в статусе `ON_APPROVAL`), а также прошлые согласующие могли иметь доступ. Логика `canUserWrite` содержала blanket override для Admin и нестрогие проверки. Также эндпоинт `/api/documents/:id/content` был уязвим (отсутствовала проверка прав). **Решение:** Переписана функция `canUserWrite` в `wopiController.ts` с жесткой привязкой к статусу и роли (Author только в Draft/Review, Current Approver только в On Approval, Admin без привилегий записи вне своей очереди). Закрыт эндпоинт `/content` проверкой `canUserWrite`. **Безопасность:** Исключена возможность внесения правок вне очереди. Администратор переведен в режим Read-Only для контента, если не является активным участником процесса.
