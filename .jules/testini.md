# ЖУРНАЛ ТЕСТИНИ (АРХИВ УЯЗВИМОСТЕЙ)

⚠️ Добавляй записи только о КРИТИЧЕСКИХ находках:
• Ошибки, которые возникали из-за специфики фреймворка.
• «Плавающие» баги (Race conditions), которые трудно поймать.
• Логические дыры в бизнес-логике, которые могли привести к потере данных.
• Уроки, извлеченные из сложных случаев отладки.

Формат: ## ГГГГ-ММ-ДД — [Тип бага] **Проблема:** [Что ломалось] **Решение:** [Как исправили навсегда]

## 2024-05-22 — [Логическая дыра / Безопасность] **Проблема:** Автор документа мог обойти процесс согласования, отправив PUT-запрос с `status: "APPROVED"`, так как метод `updateDocument` проверял только авторство, но не валидность перехода статуса. Это позволяло утверждать документы без участия согласующих. **Решение:** Добавлена строгая проверка переходов статуса в `documentController.ts`. Для не-админов запрещены прямые переходы в `APPROVED` (разрешено только из `REVIEW_REQUIRED`) и `ON_APPROVAL` (требует использования специального эндпоинта). Добавлен регрессионный тест `backend/tests/security_status_bypass.test.ts`.

## 2024-05-23 — [Целостность данных / Логическая ошибка] **Проблема:** Пользователи не могли удалить свои черновики (DRAFT), если они хотя бы раз открывали их в редакторе. Это происходило из-за ошибки Foreign Key Constraint, так как при открытии создавались записи `WopiToken` и `WopiLock`, которые не удалялись при удалении документа. **Решение:** В метод `deleteDocument` (вынесенный в `documentController.ts`) добавлены явные вызовы `prisma.wopiToken.deleteMany` и `prisma.wopiLock.deleteMany` внутрь транзакции удаления. Добавлен регрессионный тест `backend/tests/document_delete.test.ts`, проверяющий вызов всех методов удаления.
